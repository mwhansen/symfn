# Code of conduct

This project is small and its contributors are few. The rules are the ones
any working group needs, written down so that they do not depend on who is
present.

## What is expected

- Argue about the mathematics, the code and the evidence, not about the
  person. A wrong claim is corrected by a measurement or a counterexample.
- Assume a mistake before assuming bad faith. Most of this library was
  written by coding agents and is maintained the same way; a defect is a
  defect, and the record exists so that it is not made twice.
- Say what you know and how you know it.
- Give credit. The oracles this library is checked against are named in
  `NOTICE.md`; a contributor's work is named in the commit and the record.

## What is not acceptable

- Insults, personal attacks, or belittling anyone's competence, background
  or identity.
- Harassment of any kind, in the issue tracker, in pull requests, or in any
  channel about this project. Sexual language or imagery, threats, and
  publishing someone's private information all count.
- Sustained disruption: reopening a settled argument without new evidence,
  or posting so much that others cannot take part.

## Scope

This applies wherever the project is discussed under its name: the
repository, its issues and pull requests, and any channel a maintainer
represents it in.

## Reporting and enforcement

Report a problem to the maintainer, privately, through a direct message on
GitHub or the contact on the maintainer's GitHub profile. Reports are read
by the maintainer alone and the reporter's identity is not shared without
their consent.

A maintainer who receives a report will remove or edit the offending
content, and may warn, temporarily block, or permanently block the person
responsible, in proportion to what happened and whether it has happened
before. A maintainer who is the subject of a report does not handle it.
