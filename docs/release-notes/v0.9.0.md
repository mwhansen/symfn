symfn 0.9.0 is the first release: a Rust and Python library for computing
with symmetric functions, the six classical bases and every transition
between them, the Hall–Littlewood, Macdonald, LLT and Jack families above
them, and Schubert polynomials. Each basis is a distinct type over a
coefficient ring the caller chooses, every value that leaves the library is
exact or the call fails loudly, and the default build has no dependencies.

## Install

```sh
cargo add symfn        # Rust 1.87 or later
pip install symfn      # CPython 3.9 or later
```

Wheels are attached below for fourteen platforms; anything else builds from
the source distribution, which carries its Rust dependencies and needs only
a Rust toolchain. The Rust reference is at docs.rs/symfn and the Python
reference at symfn.readthedocs.io, and the `symfn-docs` tarball below holds
both, offline.

## What the version number promises

This is 0.9, not 1.0, because the surface has had no external caller yet. A
patch release (0.9.x) adds or fixes and breaks nothing. A minor release
(0.10) may break the crate's API tier and will name every break. The Python
surface, the contract nearly every consumer reaches the library through,
changes only in a minor release, never a patch. `docs/public-api.md` in the
repository states the rule and the tiers it applies to.

## Against Sage

These are the figures a Sage user decides on. Each names what Sage
dispatched to, because the two baselines differ by an order of magnitude:
a ratio against Symmetrica's C is a stronger result than a larger ratio
against Sage's own Python. All were measured on one laptop with Sage
answering out of its own code (`SAGE_DISABLE_SYMFN=1`), and every one is in
`docs/record/` with its harness, its degree ladder, and its power state.
Ratios move with degree; the degree given is the one the figure was read at.

| Computation | Ratio | Sage dispatched to |
|---|---|---|
| Kostka–Foulkes `K_{λμ}(t)`, per pair | 30–40× | its own Python (`kfpoly`) |
| Kostka–Foulkes, a whole column | 880× | its own Python (`kfpoly`) |
| Macdonald `P`, `Q`, `J`, every shape through degree 9 | 94× | its own Python |
| The `(q,t)`-Kostka matrix, degree 12 | 18× | its own Python |
| `∇e_n`, degrees 8 to 13 | 16–27× | its own Python |
| Jack `m → P`, `m → Q`, `m → J`, degree 10 | 960–1090× | its own Python |
| LLT, whole-degree tables to `k = 4` | 700–19 100× | its own Python |
| A Kronecker coefficient, degrees 12 to 24 | 40–2350× | its own Python (`itensor`) |
| Reduced Kronecker product `st[4,3]²` | 3400× | its own Python |
| Plethysm | 25–40× | its own Python |
| Classical-basis conversions, degrees 8 to 20 | 2–8× | Symmetrica (C) |
| Hall–Littlewood `Q'`, end to end | 2.5–3.4× | Symmetrica (C) |
| The `sage.combinat.sf` test suite, like for like | 1.84× | Symmetrica (C) |

Two things Sage cannot do at any speed are in this release: the exact
reduced Kronecker coefficients past the degrees `itensor` reaches, and the
Macdonald operators Δ, Δ′ and Θ, which Sage does not have.

## Against lrcalc

Sage dispatches Schur products to lrcalc, a compiled C library, so the
Littlewood–Richardson figures are not a row of the table above: they are
measured against lrcalc 2.1 directly, out of process, one invocation per case,
best of three on AC power. Every completed case agrees with lrcalc, and the
range across the sweep is 1–30×, ahead on every case above the few-millisecond
floor where the measurement is process startup. The largest rows:

| Computation | Ratio |
|---|---|
| `s[8,7,6,5,4,3]²` | 29.6× |
| `[16,13,10,7]²`, wide shapes | 18.3× |
| The largest skew measured, `[13,12..2]/[5,4,3,2,1]` | 25.4× |

`[24,20,16,12]²` does not finish within 200 seconds under lrcalc. It takes
10.1 seconds here.

Two things bound what those ratios mean. Where a product dispatches to the
counting routes, symfn uses several cores against lrcalc's one, so the
comparison is of the machine rather than of the algorithm per core. And in a
Sage session the Littlewood–Richardson computation is already compiled C:
building the Python objects for the answer costs more than computing it, so
a Sage user sees the object layer, not these ratios.
`docs/record/littlewood-richardson.md` holds the sweep with its harness.

## Sage as a consumer

This wheel does not depend on Sage, import it, or change anything when
installed beside it. The adapter that lets Sage compute with symfn in place
of Symmetrica lives on the Sage side, on a branch that has not been proposed
upstream; the README's "Under Sage" section says what it covers and how it is turned
off. Sage's use of symfn is what the `SAGE_DISABLE_SYMFN` caveat above is
about.

## What to know before relying on it

Fixed-width coefficient types have walls, stated where each family lives;
past them a call refuses or escalates, and never wraps. The modules marked
hidden in the reference are cross-check engines and product strategies whose
results are public and whose paths are not; they can move in a patch. There
is no changelog for this release, since it has no predecessor a consumer
holds; the next release names what changed.
